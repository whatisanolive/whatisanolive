If you've ever checked your guest list twice, then you'd know:

> **_Checking for duplicates is like finding out two people showed up to the party wearing the exact same outfit—you can either interrogate every single guest one-by-one, line everyone up by height, or just check the guest list at the door and call it a day._**

Finding duplicate elements is a classic rite of passage in coding interviews. It’s the kind of problem where the most brutally lazy solution works instantly on small arrays, but using it in production will have your tech lead slowly backing out of the room.

## The problem

Given an array of integers, figure out if any value appears at least twice. Return `True` if duplicates exist, and `False` if every element is unique:

```plaintext
Input:  [1, 4, 5, 2, 1, 6]
Output: True  (1 appears twice)
```

## Brute force first

The naive approach is the one your interviewer expects you to write first—mostly so they can watch you sigh. You compare every element to every other element to its right. It’s the algorithmic equivalent of checking your entire contact list to see if you accidentally saved your dentist twice.

```python
def has_duplicates(arr):
    n = len(arr)
    for i in range(n):
        for j in range(i+1, n):
            if arr[i] == arr[j]:
                return True
    return False
```

| Time | Space |
| :--- | :--- |
| $O(n^2)$ | $O(1)$ |

> **Watch out:** Running this on a large dataset will turn your CPU fan into a jet engine. Your interviewer might actually kick you out of the room for writing this, but hey... it works!

## The better approach

Instead of comparing everyone to everyone, we walk through the array once and drop numbers into a `set` like a digital coat check. Before dropping a number in, we check if it's already there. If it is, boom—duplicate found.

```python
def has_duplicates_3(arr):
    hashset = set()
    
    for n in arr:
        if n in hashset:
            return True
        hashset.add(n)
        
    return False
```

| Time | Space |
| :--- | :--- |
| $O(n)$ | $O(n)$ |

Set lookups take $O(1)$ time on average, meaning we can breeze through the whole array in a single linear pass. We trade a bit of memory ($O(n)$ space) to buy back all our processing time.

## Edge cases

- **Empty input / Single element:** Instantly returns `False` since duplicates are impossible with fewer than two items.
- **All elements identical:** Triggers an immediate return on the very first comparison step.
- **No duplicates:** Sweeps the entire array cleanly before returning `False`.

## In an interview

"You can start with a brute force double loop to show you understand the logic, but immediately pivot to a hashset or a one-line set conversion to prove you actually value system performance." Expect the classic follow-up: *"Great, now what if you have to solve this in $O(1)$ auxiliary space without modifying the original array?"*.
